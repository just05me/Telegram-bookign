# Telegram Booking Bot V2 — Техническое описание (ТЗ)

## 1. Назначение

Telegram-бот для организации записи клиентов на встречи через Telegram.
Система позволяет организаторам создавать календари с расписанием, клиентам — бронировать слоты через бота, а обеим сторонам — управлять встречами (отмена, перенос, заметки).

## 3. Модель данных (Prisma)

### User (таблица `users`)
- **id** (UUID, PK) — внутренний идентификатор
- **telegramId** (BigInt, unique) — Telegram ID пользователя
- **telegramUsername** (String?) — @username
- **firstName**, **lastName** — имя/фамилия
- **languageCode** — код языка интерфейса
- **role** — ORGANIZER | CLIENT (роль)
- Связи: один `Organizer`, много `Appointment[]`

### Organizer (таблица `organizers`)
- **id**, **userId** (FK → User), **slug** (unique, для ссылок)
- **title** — название календаря
- **description** — описание
- **defaultDuration** — длительность встречи по умолчанию (мин)
- **bufferBefore**, **bufferAfter** — буфер до/после встречи (мин)
- **maxMeetingsPerDay** — лимит встреч в день
- **bookingDeadlineDays** — горизонт бронирования (дней)
- **timezone** — часовой пояс (по умолч. UTC)
- **isActive** — активен ли календарь
- ~~**googleRefreshToken**, **googleCalendarId** — удалено~~

### AvailabilitySlot (таблица `availability_slots`)
- Рабочее время: день недели (0-6), startTime, endTime (HH:mm)
- Unique: (organizerId, dayOfWeek, startTime, endTime)

### ExceptionDate (таблица `exception_dates`)
- Исключения в расписании: конкретная дата, isAvailable, опционально своё время
- Unique: (organizerId, date)

### Appointment (таблица `appointments`)
- **organizerId**, **clientId?** (FK → User)
- **clientName**, **clientContact**, **clientTelegram**, **phoneNumber**, **instagram**, **clientNote**
- **participantsCount** — количество участников
- **selectedChoiceId?** — выбранная опция (FK → BookingOptionChoice)
- **startTime**, **endTime**, **duration** — время встречи
- **status**: CONFIRMED | CANCELLATION_REQUESTED | CANCELLED | RESCHEDULE_REQUESTED | RESCHEDULED
- **cancellationRequestedBy**, **cancellationReason**
- **rescheduleTargetTime** — целевое время при переносе
- **location** — адрес/место проведения
- **organizerNote** — заметка организатора
- ~~**googleEventId** — удалено~~

### BookingOptionGroup (таблица `booking_option_groups`)
- Группа опций: **title**, **isActive**, **choices[]**

### BookingOptionChoice (таблица `booking_option_choices`)
- Конкретный вариант: **label**, **sortOrder**
- Связь: group → BookingOptionGroup

### Session (таблица `sessions`)
- **telegramId** (BigInt, PK) — Telegram ID пользователя
- **type**, **data** (JSON)
- Используется для хранения состояний (бронирование, настройки, перенос и т.д.)

### Reminder (таблица `reminders`)
- **appointmentId** (FK), **type** (BEFORE_3D | BEFORE_1D | BEFORE_3H)
- **scheduledFor**, **sentAt**, **status** (PENDING | SENT | FAILED)

## 4. Функциональные возможности

### 4.1 Роли пользователей

- **ORGANIZER** — создаёт календарь, настраивает расписание, управляет встречами
- **CLIENT** — бронирует встречи через ссылку организатора

### 4.2 Регистрация и первый запуск

1. Команда `/start` — бот показывает описание своих возможностей и предлагает выбор роли: «Организатор» или «Участник»
   - При выборе **«Организатор»** — пользователю присваивается статус `ORGANIZER`, после чего предлагается создать календарь
   - При выборе **«Участник»** — бот просит пользователя отправить ссылку от организатора для бронирования
2. Если есть deep link (`/start <slug>`) — сразу запускает процесс бронирования
3. После регистрации организатору предлагается создать календарь кнопкой «📅 Создать календарь»

### 4.3 Команды бота

| Команда | Описание |
|---------|----------|
| `/start` | Регистрация / вход / быстрый переход к брони (со slug) |
| `/menu` | Главное меню |
| `/book <slug>` | Запустить бронь по slug организатора |
| `/my_bookings` | Список своих встреч (клиентских) |

Reply-кнопки:
- «📅 Создать календарь» — создаёт календарь организатора
- «🔍 Забронировать встречу» — инструкция по бронированию

### 4.4 Главное меню (для организатора)

Inline-меню с кнопками:

| Кнопка | Callback | Назначение |
|--------|----------|------------|
| 📅 Мои встречи | `my_appointments` | Список всех встреч (организатора и клиента) |
| ⚙️ Настройки | `settings` | Настройка календаря |
| 🕐 Расписание | `availability` | Рабочие часы |
| 🔗 Моя ссылка | `my_link` | Показать ссылку для клиентов |
| 🎯 Опции | `options_list` | Доп. услуги/опции бронирования |
| 📊 Статистика | `stats` | Статистика встреч |

### 4.5 Бронирование (клиентский флоу)

**Механизм:** сессия (объект `BookingSession`), сохраняемая в памяти + SQLite на каждый шаг.

**Шаги бронирования:**

1. **Выбор даты** — интерактивный календарь с навигацией по месяцам
   - Доступные даты: от сегодня до `bookingDeadlineDays`
   - Выходные за рамки периода — скрыты

2. **Выбор времени** — сетка свободных слотов (по `defaultDuration` минут)
   - Отображаются только свободные слоты. Занятые слоты скрыты и недоступны для выбора
   - Учитываются: рабочее расписание, буферы, уже занятые слоты (полностью исключаются из сетки), лимит встреч в день

3. **Выбор опции (опционально)** — если организатор настроил группы опций

4. **Форма заполнения**:
   - **Имя** (обязательно)
   - **Telegram @username** (опционально)
   - **Instagram** (опционально, валидация формата)
   - **Телефон** (опционально, через кнопку «Поделиться номером» или вручную)
   - **Количество участников** (по умолч. 1)
   - **Заметка** (опционально)

5. **Подтверждение** — сводка всех данных, кнопка подтвердить/отменить

6. **Создание записи**:
   - Проверка конфликтов (race condition: не занял ли кто-то слот между показом и подтверждением)
   - Проверка лимита на день
   - Создание Appointment в БД
   - Связывание с User (создание нового, если впервые)
   - Уведомление организатора о новой встрече

### 4.6 Управление встречами

**Действия для организатора:**

- **❌ Отмена** — запрос на отмену (`CANCELLATION_REQUESTED`), оппонент подтверждает или отклоняет
- **🔄 Перенос** — полноценный флоу выбора новой даты/времени через календарь
- **📍 Адрес** — организатор указывает адрес/место встречи, клиент получает уведомление
- **📝 Заметка** — организатор пишет приватную заметку (видна только ему)
- **◀️ Назад / 🏠 Меню** — навигация

**Действия для участника (клиента):**

- **❌ Отмена** — запрос на отмену (`CANCELLATION_REQUESTED`), оппонент подтверждает или отклоняет
- **🔄 Перенос** — полноценный флоу выбора новой даты/времени
- **◀️ Назад / 🏠 Меню** — навигация

**Система отмен:**

1. Любая сторона инициирует отмену → статус `CANCELLATION_REQUESTED`
2. Другая сторона получает уведомление с кнопками:
   - «✅ Подтвердить отмену» → статус `CANCELLED`, обе стороны уведомлены
   - «❌ Отклонить» → статус возвращается к `CONFIRMED`

**Система переноса (реализована полностью):**

1. Любая сторона инициирует перенос → создаётся `RescheduleSession` (тип сессии `reschedule`)
2. Открывается интерактивный календарь для выбора новой даты (`cal:rs:*` callback)
3. После выбора даты показываются свободные слоты с учётом занятости
4. При выборе времени проверяется пересечение с другими встречами
5. Обновляется статус на `RESCHEDULE_REQUESTED`, сохраняется `rescheduleTargetTime`
6. Другая сторона получает уведомление с кнопками:
   - «✅ Подтвердить перенос» → статус `RESCHEDULED`, обе стороны уведомлены
   - «❌ Отклонить» → статус возвращается к `CONFIRMED`

### 4.7 Настройки календаря (для организатора)

Организатор может изменить:

| Параметр | Описание | Диапазон |
|----------|----------|----------|
| Название | Название календаря | 1-100 символов |
| Описание | Описание для клиентов | 0-500 символов |
| Длительность (defaultDuration) | Длительность встречи (мин) | 15-120 |
| Буфер до (bufferBefore) | Пауза перед встречей (мин) | 0-60 |
| Буфер после (bufferAfter) | Пауза после встречи (мин) | 0-60 |
| Макс. встреч/день (maxMeetingsPerDay) | Лимит | 1-50 |
| Дней для брони (bookingDeadlineDays) | Горизонт бронирования | 1-365 |

### 4.8 Управление расписанием (для организатора)

- По дням недели (Пн-Вс)
- Можно добавлять несколько слотов на день (например, 9:00-13:00 и 14:00-18:00)
- Добавление «на все дни» одной кнопкой
- Редактирование существующих слотов
- Удаление слотов
- Ввод времени: гибкий парсинг («9» → 09:00, «9:30» → 09:30, «09:00» → 09:00)

### 4.9 Опции бронирования (доп. услуги, для организатора)

- Создание групп опций (например, «Тип услуги»)
- Добавление вариантов в группу (например, «Консультация», «Массаж»)
- Клиент выбирает опцию при бронировании
- Редактирование названия группы
- Удаление группы (с очисткой ссылок в Appointment)

### 4.10 Адрес встречи

- Организатор может указать/изменить адрес проведения для конкретной встречи
- Клиент получает уведомление с адресом после сохранения

### 4.11 Напоминания

- Cron-задача с интервалом 5 минут
- 3 типа напоминаний:
  - `BEFORE_3D` — за 72 часа (3 дня)
  - `BEFORE_1D` — за 24 часа (1 день)
  - `BEFORE_3H` — за 3 часа
- Отправляются и организатору, и клиенту
- Дедупликация: проверка, не было ли уже отправлено напоминание данного типа для данной встречи
- Поиск встреч по 10-минутному окну (±5 мин от целевого времени)

### 4.12 Google Calendar интеграция (удалена)

Google Calendar интеграция полностью удалена из кода:
- Удалены файлы `api/google.ts` и `lib/google.ts`
- Удалён OAuth-флоу (эндпоинты `/api/google/auth`, `/api/google/callback`)
- Удалены поля `googleRefreshToken`, `googleCalendarId`, `googleEventId` из моделей (на уровне кода; в схеме Prisma поля сохранены для обратной совместимости)
- Удалены переменные `.env`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `ENCRYPTION_KEY`
- HTTP-сервер Express запускается всегда, но только для health check

### 4.13 Статистика (для организатора)

Детальная статистика по встречам:

- Всего встреч
- Запланировано (CONFIRMED)
- Отменено (CANCELLED)
- Ожидают отмены (CANCELLATION_REQUESTED)
- Перенесено (RESCHEDULED)
- Ожидают переноса (RESCHEDULE_REQUESTED)
- Сегодняшние встречи (количество)
- Встречи на текущую неделю
- Среднее количество участников на встречу
- Самая загруженная дата

### 4.14 Управление сессиями

- In-memory cache с lazy persist в SQLite (таблица `sessions`)
- AutoPersist через Proxy: мутации объекта сессии автоматически сохраняются в БД
- Типы сессий: booking, settings, availability, options, address, note, **reschedule**
- При старте бота сессии загружаются из БД в кеш
- `telegramId` в таблице сессий — BigInt (исправлено с Int)

## 7. Примечания

- Бот работает в polling-режиме (на локальной машине без HTTPS)
- База данных — SQLite (файл `ruvector.db`), docker-compose с PostgreSQL существует, но не используется
- Интерфейс — полностью на русском языке
- Все временные слоты работают в UTC (часовой пояс организатора заложен в схеме, но полноценная конвертация не реализована)
- Markdown-форматирование в сообщениях экранируется (`escMarkdown`) для защиты от некорректного отображения
- Генерация `.ics`-файлов реализована, но не вызывается в рантайме
- Каждый текстовый обработчик проверяет тип активной сессии внутри себя и молча выходит, если сессия не соответствует — это позволяет всем обработчикам сосуществовать в одном `message:text` middleware
- Google Calendar интеграция полностью удалена; OAuth-эндпоинты и связанный код вырезаны
- Перенос встреч полностью реализован (интерактивный календарь → выбор слота → уведомление второй стороны)
- Напоминания: `BEFORE_1H` заменён на `BEFORE_3D` (3 типа: 3 дня, 1 день, 3 часа)
